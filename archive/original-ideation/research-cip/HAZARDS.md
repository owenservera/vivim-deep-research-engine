# HAZARDS — cross-loop defect patterns (research-cip)

Patterns discovered across research iterations. Each new `FRAMING.md` is seeded
with the relevant hazard IDs so later targets are attacked with prior lessons.
When a NEW pattern is found, append it here via
`bun run scripts/research-loop.ts hazard "<text>"` or `pwsh scripts/check_budget.ps1`.

Seeded from vivim-final loop (H1-H15) — translated to CIP domain. CIP analog noted.

- **H1 — Permissive `??`/default in lookup maps (fail-open).** A map lookup that falls back to the *permissive* value on miss, e.g. `TIER_RANK[tier] ?? 0`, `config.get(k, DEFAULT)` where DEFAULT is lenient. In CIP: `DEFAULT_CONFIG` + `load_config` merging `config.default.toml` with `.cip/config.toml` may silently fill missing keys with permissive defaults (e.g. `max_file_size`, `exclude_patterns`). Check every `dict.get(..., default)` / `??` / `or` where default is the open option. *Found in vivim-final: capability-resolution `tierRank`.*
- **H2 — Provenance/metadata disagrees with the actual value path.** A `*_from` / `source` / `provenance` field populated on a different code path than the value it describes. In CIP: `Finding.suggestion` vs `rule` provenance, `edges.kind` provenance vs actual `symbols.body` path, `snapshots` health vs `analysis.repo_health_report` components. *Found: capability-resolution `overrideSources`.*
- **H3 — Case/whitespace sensitivity in enum-like tokens.** Tier/status strings compared without normalization. In CIP: Windows filesystem is case-insensitive but `store` does `path LIKE`/`=` which may be case-sensitive; `resolve_import` spec handling (`./Foo` vs `./foo`), `language` detection by extension, config keys, `process.env` variable names on Windows vs Linux. *Found: min_plan_tier casing.*
- **H4 — Unparseable/empty rule defaults to "satisfied"/"allowed" (fail-open).** A parser that returns `true` when rule can't be parsed. In CIP: `parsers.py:parse_file` returning `None` → `prepare_file` silently produces tier-only file with no symbols; `stack/rules.py` rule that catches but `findings.append(info)` masks failure; `indexer._parse_worker` `except: return (path,None)` swallowing parse errors. *Found: satisfiesExistentialRule.*
- **H5 — Paired read paths can diverge.** `search` vs `resolve` / `sync` vs `retrieve` reading from different store methods. In CIP: `indexer.sync` writes to `files/chunks/symbols/edges` but `retrieve.lex_search` reads `chunks_fts2`/`chunks_fts`/`chunks`, `retrieve.vec_search` reads `vectors`, `gapfill.coverage` reads `edges tested_by`, `analysis.repo_health_report` reads `findings` — stale FTS or vectors vs chunks cause `search ⊆ index` invariant to break. *Found: capability-resolution search/resolve.*
- **H6 — Missing-context vacuous satisfaction.** An existential/policy check vacuously true when caller omits context. In CIP: `retrieve.context` with `symbol=None` and empty `query` still returns a pack; `store.connect` on missing `.cip/` auto-creates; `gapfill` with zero symbols yields `score 100 - 0` (healthy) instead of unknown. *Found: capability-resolution.*
- **H7 — Numeric/string coercion in comparisons.** `String(x) === expected` mixing types. In CIP: `store.set_meta` stringifies every value (`str(value)`), so `get_meta(..., 0)` truthiness, `time.time()` vs `REAL` vs `TEXT`, `hash` hex vs bytes, `size` vs `lines` integer/string coercion in `files` table.
- **H8 — Unescaped wildcard metacharacters (%/_) in query strings and LIMIT/truncation applied before the precise filter — drops valid results or yields false positives.** In CIP: `retrieve.lex_search` does `text LIKE ?` with `f"%{query}%"` without escaping `%`/`_`; `gapfill.api`/`deps` use `LIKE '%migration%'`; `store.bulk_delete_paths` with `IN` chunking may truncate; `audit` does `path LIKE ?` with user-controlled path. *Found: capability-store-impl.*
- **H9 — Denylist/blocklist guards for code execution (`new Function`/eval/DSL) FAIL OPEN.** Blocklist only blocks enumerated tokens. In CIP: `sandbox`/`safe-eval` analog would be `exec`/`eval` in `lib/cipkg`? Check `server.py`, `embed.py` `urllib.request.urlopen` without allowlist, `store` raw SQL interpolation via `%s` table name in `bulk_delete_paths` (`"DELETE FROM %s WHERE %s IN (%s)" % (table, col)` — table/col are caller-controlled, not parameterized). *Found: safe-eval.*
- **H10 — Inert/premature policy options and flags silently overridden by a coarser threshold.** A documented control that cannot actually gate anything because no enum maps to it or is vetoed by another setting. In CIP: `config.default.toml` flags like `[audit] ignore_rules`, `[vector] backend = "sqlite" | "sqlite-vec"` where `sqlite-vec` experimental may be ignored; `[embed] backend = "auto"` falling through; `tacit` `autostart` never read. *Found: policy-engine.*
- **H11 — Silent no-op on empty/edge inputs, and `??` default that swallows a falsy-but-valid value (0, '').** A routing/dispatch that resolves to empty still returns success. In CIP: `indexer.sync` with `dirty=[]` but `deleted=None` still runs `resolve_symbol_edges(None)` full scan; `store.bulk(con, sql, [])` guard returns 0 silently; `retrieve.search` with `query=""` returns `[]` not error; `deps()` with missing `pyproject.toml` returns `0` not warning. Also `max_file_size = 0` vs unset confusion (falsy-but-valid). *Found: provider-mux.*
- **H12 — Failover/re-dispatch without idempotency causes duplicate side effects.** A retry loop re-sending same input to next target with no idempotency key. In CIP: `embed.get_embedder` retry, `daemon` port fallbacks `daemon_port_min..max`, `indexer` `ProcessPoolExecutor` retry on exception (re-runs `_parse_worker` serially), `store.write_snapshot` `INSERT OR REPLACE` vs `INSERT` duplicate ts collision, `mcp` tool retry without dedup. *Found: router.*
- **H13 — Vocabulary/enum mismatch across related fields + returning unvalidated references.** Two related enums use different value sets, setter maps only SOME values. In CIP: `Symbol.kind` enum in `ontology.json` (`class/function/method/interface/type/const/module/test`) vs `files.language` (`python/javascript/...`) vs `chunks.tier` (`code/doc/config`) mismatch; `edges.kind` set drifts (`imports/calls/references/tested_by/contains/exports/...`); `store` returning `symbol_id` that no longer exists after `bulk_delete_paths`; `routes.kind` (`api/page/layout`) vs `nextjs` detection. *Found: kernel-registry.*
- **H14 — Missing/empty evidence defaults to a PERMISSIVE/POSITIVE value in a trust/risk/score computation (fail-open).** Absent data scored as "good." In CIP: `gapfill.score` with `fresh=False → -15` but `dead_ratio=0` when `symbols=0` gives `score 85` (healthy) for empty index; `analysis._calculate_health_score` with `total_symbols=0 → coverage_pct 0` but `quality_score 100` and `complexity_score 80` yields `44/100`? Audit with zero findings yields clean. Empty `.cip/data` vs populated divergence. *Found: trust-score.*
- **H15 — Divergent side effects across two code paths that should be equivalent.** Two branches representing same operation produce different persistent side effects. In CIP: `indexer.prepare_file` tier `code` vs `doc` vs `config` produce different tables touched; `_bulk_write` deletes `vectors` per `chunk_ids` but `remove_file` deletes per `path`; `sync` with `do_embed=True` vs `do_embed=False` leaves `vectors` stale vs fresh but `store.get_meta("embedder_name")` is same; `gitindex` vs `indexer` dual indexing of same file yields duplicate symbols. *Found: streaming-protocol.*
